# Modules

Each module owns its tables and exposes services; other modules call those services, never its tables (ADR-001 section 2). Directories are created when a module gets its first real code.

- `identity`: users, sessions, roles, MFA. Milestone 1 (step 2, ADR-002). `auth-config.ts` (Better Auth setup), `auth.ts` (server instance), `schema.ts` (tables), `policy.ts` (`getActor`, `can`, `requireActor`, `requireStaff`), `roles-service.ts` (staff roles; enforces the self-change and last-super-admin rules and writes audit rows) and `cli/role-admin.ts` (staff roles from the operator command line), `rate-limit.ts` (per-email limits), `export.ts` (identity part of the data export), `ui/` (auth forms).
- `profiles`: public profile, private professional details, experience, governorate reference data. Milestone 1 (step 3, ADR-003). `schema.ts` (tables), `constants.ts` (allowed values, limits), `policy.ts` (`can` for `profile.read`, `profile.update`, `professionalDetails.read`, `professionalDetails.update`, reusing identity's Actor), `validation.ts` (Zod parsing shared by forms and services, error codes), `governorates.ts` (`listGovernorates`, the reference list other modules read), `service.ts` (all database access; owner ids only from the Actor; `getProfileForViewer` applies visibility; `exportOwnData`), `actions.ts` (server actions), `ui/` (owner forms, member view).
- `uploads`: private files (ADR-004, 4a). `schema.ts` (`upload` table), `constants.ts` (purposes, statuses, reject reasons, limits), `detect.ts` (magic-byte allow-list: JPEG, PNG, WebP), `multipart.ts` (bounded form reading), `policy.ts` (`can` for `upload.create`, `upload.readStatus`, `upload.view`; owner only), `service.ts` (`admitUpload`, `createUpload`, `getUploadStatus`, `issueSignedUrl` with a caller-supplied `ViewAuthorizer`), `http.ts` (handlers behind `/api/uploads`), `processing.ts` (worker: scan, re-encode, dead-letter handling). Other modules reference uploads by id and view them through `issueSignedUrl`.
- `verification`: professional verification (ADR-004, 4b). `schema.ts` (`verification_submission`, `verification_document`, append-only `verification_decision` and `document_access_log`), `constants.ts` (credential types, statuses, document kinds, reason codes, limits), `national-id.ts` (format, birth date, age and governorate checks, masking; browser-safe), `keys.ts` (national ID keys from the environment; encrypt, decrypt, keyed hash over `src/shared/crypto`), `validation.ts` (submission and decision forms, error codes), `policy.ts` (`can` for owner and reviewer actions; reviewers need identity's `verification.review`, never their own submission, private data only while pending), `service.ts` (all web-side database access: submit, own status, badge, export, queue, review details, logged reveal and document view, decisions), `jobs.ts` (worker side: emails, daily expiry), `http.ts` (reviewer document route), `actions.ts` (server actions), `deps.ts` (production wiring), `ui/` (user form and status card, reviewer controls). Other modules use `getVerificationBadge` and `exportOwnVerification`.
- `organizations`: pharmacies and chains, membership (ADR-005, step 5). `schema.ts` (`organization`, `organization_member`, `organization_invitation`, append-only `organization_audit`), `constants.ts` (kinds, member roles, invitation statuses, audit actions, limits), `validation.ts` (organization and invitation forms, error codes), `policy.ts` (`can` with the actor's role in the organization, loaded by the service; owner and recruiter, ADR-005 amendment; `jobs.manage` for step 6), `service.ts` (all web-side database access; every write locks the organization row and writes an audit row; `exportOwnOrganizations`), `jobs.ts` (worker: invitation email), `actions.ts` (server actions), `ui/` (forms, member and invitation lists). Step 6 (jobs) authorizes through this module's `can`.
- `jobs`: job posts, moderation of first posts, the public board (ADR-006, step 6a) and applications (ADR-007, step 6b). `constants.ts` (statuses, transitions, reason codes, limits, application states and limits), `schema.ts` (`job`, append-only `job_moderation_decision` and `job_event`, `job_application`, append-only `application_event`), `validation.ts` (job, decision, search and application forms, error codes), `policy.ts` (`can` for employer actions, using the actor's role from organizations' `getRoleInOrganization`, and for moderation with identity's `moderation.access`; `canApplication` for applicant and employer application actions), `application-snapshot.ts` (Zod schema of the profile snapshot an application shares; profiles' `getOwnApplicationShare` builds it), `applications.ts` (applicant and employer application services: apply, list own, withdraw, move through the states, export), `service.ts` (all web-side database access; search text normalized with `src/shared/text/search.ts`; organization names and kinds from organizations' `getPublicOrganizations`), `jobs.ts` (worker: expiry, the creator's email and the applicant's `applications.notify` email), `actions.ts` (server actions), `ui/` (forms, board, member and review views, apply and application views).
- `shifts`: shift coverage and booking. Milestone 2.
- `listings`: pharmacy sale and rental listings. Milestone 3.
- `billing`: subscriptions and payments. Milestone 3.
- `notifications`: channels, preferences, outbox. Milestone 1 (email), extended later.
- `admin`: audit log and staff role management (ADR-008, step 7a). `schema.ts` (append-only `admin_audit`), `constants.ts` (audit actions, actor kinds, target types, page size), `audit.ts` (leaf writer `recordAudit` and `auditIp`, called inside other modules' transactions), `service.ts` (`listStaff`, `changeStaffRole`, `searchAudit`; super admins only), `actions.ts` (server actions), `ui/` (roles and audit pages). Step 7b adds suspension, job reports and takedowns.
